Extraction for Risk — 后置决策模型（ReportCheck）

Genos 解析收入文件；ReportCheck 决策模型把一个申请的全部文件解析结果聚合为申请级自动决策：自动拒绝 / 转人审 / 自动通过。目标：每条自动规则首位命中 Precision ≥ 95%，在此前提下提高自动决策 coverage。

Genos 与 ReportCheck 是一先一后、经文件槽位衔接的两个模型产品：解析模型地区无关地输出结构化 JSON；决策模型把同一申请的全部文件结果聚合成一个申请级决策，由 Dify 编排、Risk Policy 执行。

上游 · 文件级

Genos 解析模型

每份 payslip / bank statement / tax / BIR 2316 / COE 单独走 QC Model 拦截 → 反作弊 → LLM OCR，产出结构化字段与 QC、篡改、元数据证据。

产物：每份文件一个结构化 JSON（resp_raw），落入申请的文件槽位（每地区 6–8 个槽）。
下游 · 申请级

ReportCheck 决策编排

Dify 编排：Start 带入申请上下文与全部文件槽 → mid UDF 按文件类型计算规则信号（1 命中 / 0 未命中 / -1 缺参 / -1001 未上传）→ combine 聚合为申请级 *_reject / *_screen flags。

产物：一行一个申请（workflow_flow_no）的 0/1 flags。
执行 · 按优先级

Risk Policy

按确认的 priority 取首位命中规则执行：自动拒绝（带 Report01–13 原因码）、转人审（生成 Ops screening 工单）或自动通过。ID 无命中转人审，PH 无命中自动通过。

产物：申请级终态；仅人审单进入 Ops 复核。
一个申请、多种文件同一申请可混合提交多份、多类型文件；文件级信号必须聚合到申请级才产生终态，规则 Precision 也只在申请级计算。
精度优先的门禁每条自动规则首位命中 Precision ≥ 95% 才可上线；评测用 Ops / 用户确认的申请级真值（approve / reject），不用规则自身信号自证。
地区独立实现ID 与 PH 各自维护规则逻辑、优先级与 Risk Policy，互不共享；文件输入契约由真实线上流量抽样验证。

决策模型靠每周一的自动评测循环迭代：只读拉取线上流量与终态 → 本地回放计算逐规则首位 Precision 与线上 coverage → 分层抽样复核源文件 → 可信标签入 Golden → 生成简报；改动经 Owner 批准后，携配置 JSON 与 E2E 用例在 Dify / Risk Policy 手动上线，回到线上，闭环。图内可缩放、搜索、切换明暗主题，右上角可播放「迭代闭环」视角。

线上 coverage 口径：近 7 天（2026-09-03～09-09）spj / kredit 申请的自动拒绝 / 人审 / 自动通过占比；Precision 为申请级首位命中，给出可信标签与 holdout（固定 1/3 抽样）两个口径。数据截至 2026-09-10。
